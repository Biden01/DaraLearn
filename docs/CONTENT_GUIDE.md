# Контент пилота: как собрать карту навыков и банк заданий

Шаблоны лежат в `content/templates/`, собираются командой
`cd backend && PYTHONPATH=. python scripts/build_content_templates.py` (из текущих материалов `data.py`).

| Файл | Что в нём | Куда загружается |
| --- | --- | --- |
| `skills_map_template.xlsx` | Карта навыков: slug, названия kk/ru, время, prerequisite, теория; колонки для проверки учителем | `POST /api/content/admin/skills/import` |
| `tasks_template.xlsx` | Пустой лист `tasks` для новых заданий, листы «Инструкция», «Покрытие», «На проверку» | `POST /api/content/admin/tasks/import` |

Выгрузка текущего состояния из системы: `GET /api/content/admin/skills.xlsx`, `GET /api/content/admin/tasks.xlsx`.
Чего не хватает прямо сейчас: `GET /api/content/admin/coverage` (по навыкам: что есть, чего недостаёт, готов ли навык).

## Сроки (план работ)

| Задача плана | Срок | Критерий |
| --- | --- | --- |
| 5. 20–40 навыков и карта связей | 28.10 | Карта проверена учителем (`teacher_ok = да` в каждой строке) |
| 6. Первые 50–80 заданий | 30.10 | Каждое привязано к навыку |
| 13. 100–150 заданий, теория, промпты | 05.11 | Теория есть по каждому навыку на kk и ru |

## Минимум на навык

Диагностических 1, практических 4, проверочных 3 (всего 8). Это не прихоть: дневной план берёт 4 практических и 3 проверочных
задания, которых ученик ещё не видел; при нехватке задания повторяются, и «отсроченная проверка» перестаёт быть независимой.
Сейчас в системе 12 навыков и 60 заданий; до минимума по этим навыкам не хватает 36 заданий.

## Правила хорошего задания

1. Одно задание проверяет один навык; четыре варианта, неверные — типичные ошибки учеников (это основа гипотез причин).
2. `p` — практика (подсказки разрешены), `v` — проверка без помощи, `d` — диагностика. Верный вариант — номер 1–4.
3. Для `v`-заданий нужны разные форматы одного навыка: похожая задача и «новая ситуация» (другая формулировка).
4. `explanation` пишется по шагам: для практики это текст «полного разбора», который Tutor показывает на последней ступени подсказок.
5. Обе языковые версии обязательны. Не копировать из сборников без права на использование.
6. Каждое задание проверяет второй человек до загрузки (лист «На проверку»).

## Теория

Tutor объясняет только то, что есть в теории навыка; чего там нет, он не выдумывает и зовёт учителя. Поэтому теория — это
краткая проверенная база: правило, формула (`$ `), заметка «Запомни» (`! `), 1–2 типичные ошибки.

## Что не покрывается автоматически

- Изменения контента через админку и импорт пишутся в журнал (`/api/admin/audit`), но **версий заданий и теории пока нет**:
  правило плана работ «правила, промпты и задания меняются только новой версией» требует отдельной доработки либо дисциплины
  («после старта пилота 07.11 задания не редактируем, а добавляем новые и архивируем старые»).
- Примеры решений (`examples`) в Excel не редактируются; они остаются как есть при обновлении навыка.
