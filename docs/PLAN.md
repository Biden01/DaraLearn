# План V0 — Student Success OS (DaraLearn)

Рабочий план первой версии. Источник требований — командная презентация
«Student Success OS: от идеи к V0» (`/home/era/docs/Student_Success_OS.pdf`).
Статус на 2026-10-20: в проде лендинг и приём заявок; модули продукта — заглушки.

## 1. Цель V0

Проверить гипотезу: полный цикл **Понять → Помочь → Проверить** в одной системе
даёт измеримый независимый прогресс ученика и снижает нагрузку учителя.

Критерий готовности к пилоту — «первое работающее демо»: один ученик, один навык,
путь *загрузка ответа → рекомендация → занятие → новая проверка → обновлённое состояние*
проходит без ручных вмешательств.

## 2. Границы V0

| В V0 | После проверки гипотез |
|---|---|
| Одна школа, один предмет | Расширение охвата |
| 20–40 навыков с зависимостями | Дополнительные темы |
| 150–300 проверенных заданий | Расширение банка |
| Понятные правила решений (Decision Engine) | Более сложные модели |
| AI Tutor, Teacher Action Feed, Adviser Lite | Расширенные помощники |
| Импорт Excel/CSV, ручной разбор исключений | Интеграции и автоматизация |

Вне V0: рейтинги, платная поддержка, интеграции с внешними системами школы, мобильные приложения.

## 3. Логика системы

Цикл: **Данные → Состояние → Решение → Выполнение → Результат → Состояние**.

1. **Данные** (`events`): ПКС / БС / практика / Tutor → Learning Events.
2. **Состояние** (`state`): Proof Engine → Student State (уверенность, динамика, последняя проверка).
   Практика с подсказками и независимая проверка учитываются отдельно. Мало данных → «недостаточно данных».
3. **Решение** (`decisions`): Root Cause Investigation формирует гипотезы (базовая тема / условие задачи / стратегия),
   Decision Engine выбирает следующее действие по правилам.
4. **Выполнение** (`tutor`, `verification`): AI Tutor / учитель / куратор, Execution Tracking.
5. **Результат** (`verification`): Verification / Outcome Engine, обновление Student State.

### Правила Decision Engine (пороги согласовать до пилота)

| Ситуация | Следующее действие | Порог (предварительно) |
|---|---|---|
| Недостаточно данных | Дополнительная диагностика | < 3 событий по навыку |
| Пробел в базовом навыке | Занятие по базовой теме | proof базового навыка < 0.5 |
| Трудность с текущим навыком | AI Tutor | proof навыка < 0.6, базовые ≥ 0.6 |
| Повторная помощь AI без прогресса | Подключение учителя | 2 сессии Tutor без роста независимого proof |
| Не выполняется учебный план | Подключение куратора | выполнение плана < 50 % за период |
| Общая проблема у группы | Групповое объяснение | ≥ 30 % класса с пробелом в одном навыке |

### AI Tutor: 9 этапов

Определить старт (1 цель, 2 диагностика, 3 первая попытка) → Поддержать (4 подсказки, 5 объяснение,
6 разобранный пример) → Проверить (7 самостоятельная задача, 8 новая ситуация, 9 мини-проверка).
Вход: состояние, ошибки, теория; цель задаёт Decision Engine. Выход: ответы, ошибки, подсказки, результат проверки.

## 4. Модель данных по модулям

| Модуль | Таблицы V0 |
|---|---|
| `school` | `schools`, `users` (роль: student / teacher / curator / admin), `classes`, `class_members` |
| `content` | `skills`, `skill_links` (prerequisite), `theory` (формулы, объяснения, примеры, типичные ошибки), `tasks` (навык, сложность, правильный ответ, назначение: diagnostic / practice / verification) |
| `events` | `assessments` (ПКС/БС/импорт), `learning_events` (ученик, навык, задание, ответ, верно/нет, подсказки, источник, время) |
| `state` | `student_skill_state` (proof_practice, proof_independent, confidence, trend, last_check_at, status) |
| `decisions` | `hypotheses` (ученик, навык, тип, доказательства, статус), `recommendations` (правило, действие, статус: new / accepted / changed / rejected / done) |
| `tutor` | `tutor_sessions` (цель, этапы 1–9, результат), `tutor_turns`, `llm_calls` (модель, токены, стоимость) |
| `verification` | `checks` (отсроченная проверка), `outcomes` (до/после, вывод), `teacher_actions` (feed), `adviser_cases` (план, посещаемость, период) |
| `leads` | `leads` — готово |

Общие поля: `created_at`, `source`, `actor_id`; журнал изменений (`audit_log`) для действий учителя/куратора.

## 5. API-контур V0 (`/api/...`)

- `POST /auth/login`, `GET /me`
- `GET /school/classes`, `GET /school/classes/{id}/students`
- `GET /content/skills`, `POST /content/skills/import`, `GET /content/tasks?skill=`
- `POST /events/import` (Excel/CSV), `POST /events` (из Tutor), `GET /events?student=`
- `GET /state/students/{id}`, `GET /state/classes/{id}` (тепловая карта навыков)
- `POST /decisions/run?student=` → гипотезы + рекомендация, `GET /decisions/feed?teacher=`
- `PATCH /decisions/{id}` (accept / change / reject)
- `POST /tutor/sessions`, `POST /tutor/sessions/{id}/turn`, `POST /tutor/sessions/{id}/finish`
- `POST /verification/checks`, `POST /verification/checks/{id}/result`, `GET /verification/adviser?curator=`

## 6. Интерфейсы

| Роль | Экран V0 |
|---|---|
| Ученик | План на сегодня, занятие с Tutor, прогресс по навыкам |
| Учитель | Класс, анализ по навыкам, Teacher Action Feed (принять / изменить / отклонить) |

## 8. Метрики пилота

- Независимый прогресс: доля навыков, где proof_independent вырос после помощи.
- Нагрузка учителя: время на проверку и разбор ошибок до/после.
- Выполнение действий: доля принятых и выполненных рекомендаций.
- Удобство: короткий опрос учеников и учителей.

«До/после» на 5 задачах — предварительный сигнал, а не доказательство эффекта продукта.
