## 1. Цель V0

Проверить гипотезу: полный цикл **Понять → Помочь → Проверить** в одной системе
даёт измеримый независимый прогресс ученика и снижает нагрузку учителя.

Критерий готовности к пилоту — «первое работающее демо»: один ученик, один навык,
путь *загрузка ответа → рекомендация → занятие → новая проверка → обновлённое состояние*
проходит без ручных вмешательств. Сейчас этот путь покрыт автотестом `tests/test_fake_pilot.py` (API), в браузере — вручную.

## 3. Логика системы

Цикл: **Данные → Состояние → Решение → Выполнение → Результат → Состояние**.

1. **Данные** (`events`): ПҚС / БС (импорт Excel/CSV, длинный и широкий формат), практика, Tutor → Learning Events.
2. **Состояние** (`state`): Proof Engine → состояние ученика по навыку. Практика с подсказками и независимая проверка
   учитываются отдельно; «освоено» — только при независимо подтверждённом результате.
3. **Решение** (`decisions`): гипотезы причины (базовая тема / условие задачи / стратегия) и правила Decision Engine.
4. **Выполнение** (`plan`, `tutor`): план на день от цели месяца, AI Tutor, учитель, куратор.
5. **Результат** (`verification`): отложенная проверка (через 48 ч), Outcome Engine, обновление состояния.

### Правила Decision Engine (`backend/app/modules/decisions/rules.py`, версия `decision-v1`)

Пороги зафиксированы до пилота и меняются только новой версией правил.

| Ситуация | Следующее действие | Порог |
|---|---|---|
| Трудность с навыком | Занятие с AI Tutor | независимый proof < 0.6 |
| Практика получается, самостоятельно — нет | Разбор стратегии | practice ≥ 0.7 при низком независимом |
| Общая проблема у группы | Групповое объяснение | ≥ 30 % класса, минимум 2 ученика |
| Tutor не справляется | Подключение учителя | низкая уверенность Tutor или кнопка «Позвать учителя» |
| Не выполняется учебный план | Очередь куратора | выполнение плана < 30 % |

### План ученика (`plan`)

Цель месяца к ПҚС → 4 недели по непокрытым темам → тема на каждый день → план на день
(занятие с Tutor, закрепление, мини-проверка; объём фиксирован).

### AI Tutor: 9 этапов

Определить старт (1 цель, 2 диагностика, 3 первая попытка) → Поддержать (4 подсказки, 5 объяснение,
6 разобранный пример) → Проверить (7 самостоятельная задача, 8 новая ситуация, 9 мини-проверка).
Tutor объясняет только по теории навыка; чего там нет — зовёт учителя. Лимит — 60 сообщений на ученика в сутки.
Без `LLM_API_KEY` работает заглушка.

## 7. Метрики пилота

- **North Star:** Incremental Verified Learning Gain — рост независимого результата treatment минус рост control.
- Независимый прогресс: доля навыков, где proof_independent вырос после помощи.
- Выполнение действий: доля принятых и выполненных рекомендаций (цель ≥ 60 %), выполнение плана (цель ≥ 60 %).
- Нагрузка учителя: минуты в неделю на проверку работ и разбор ошибок до/после. Учитель вносит раз в неделю в разделе «Замер времени»
  (стартовый замер — 1–2 обычные недели до 07.11); в «Метриках» сравниваются только учителя с замерами и до, и после, всего и по группам.
- Удобство: короткий опрос (5 вопросов, оценки 1–5 и комментарий) — приглашение на главной у ученика и в «Моих классах» у учителя.
  Итоги по ролям и группам и комментарии без имён — в «Метриках». Повторная волна — новое значение `SURVEY` в `analytics/feedback.py`.

«До/после» на 5 задачах — предварительный сигнал, а не доказательство эффекта продукта.
